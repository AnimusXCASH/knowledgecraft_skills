# Getting Started with KnowledgeCraft

This guide answers the practical questions first:

1. **Where do I put my research paper?**
2. **Where do I run OpenCode?**
3. **What do I type?**
4. **Where do the generated files appear?**
5. **Which workflow should I choose?**

---

# 1. Recommended Project Layout

KnowledgeCraft separates **user input** from **generated state**.

Use this structure:

```text
your-project/
├── AGENTS.md
├── papers/                         ← PUT RESEARCH PAPERS HERE
│   ├── paper-1.pdf
│   └── paper-2.pdf
├── .opencode/
│   └── skills/
│       └── ...
└── .knowledgecraft/                ← GENERATED BY KNOWLEDGECRAFT
```

The important distinction is:

```text
papers/
= source files you provide

.knowledgecraft/
= generated registry, extraction, grounding, insights, drafts, QA, calendars, analytics
```

Do **not** manually copy a PDF into `.knowledgecraft/research/grounded/`.

The grounding directory is for generated source cards and claim ledgers, not raw papers.

The repository includes a `papers/.gitignore` pattern so locally added papers are not accidentally committed.

---

# 2. Where Can the Paper Be Located?

## Recommended: `./papers/`

Example:

```text
D:\my-project\papers\Aalberg_2016.pdf
```

Then start OpenCode from:

```text
D:\my-project
```

and refer to the paper as:

```text
./papers/Aalberg_2016.pdf
```

## Another folder is also fine

You can give KnowledgeCraft an explicit path:

```text
Process D:\PhD\Papers\Aalberg_2016.pdf for my research knowledge base.
```

or a relative path:

```text
Process ../research/Aalberg_2016.pdf for my research knowledge base.
```

KnowledgeCraft should track the actual source path through `research-library`.

You do not need to duplicate the paper inside `.knowledgecraft/`.

# 3. Start OpenCode from the Project Root

Windows example:

```powershell
cd D:\my-project
opencode
```

If you installed another OpenCode command name, use that command instead.

Starting from the project root allows OpenCode to see:

```text
AGENTS.md
.opencode/skills/
papers/
.knowledgecraft/
```

# 4. Choose Your Usage Mode

KnowledgeCraft supports three main modes:

```text
A. Academic / Research
B. LinkedIn / Content
C. Combined Research → LinkedIn
```

You can also call individual specialist skills directly.

# 5. Academic / Research Mode

Use this when your goal is:

- building a research knowledge base;
- processing academic papers;
- evidence synthesis;
- PhD knowledge work;
- claim extraction;
- research insight generation;
- research-to-practice interpretation.

Typical workflow:

```text
paper
  ↓
research-library
  ↓
research-source-grounder
  ↓
research-insight-miner
  ↓
reusable research knowledge
```

## One paper — easiest prompt

Put:

```text
papers/my-paper.pdf
```

in the project, then type:

```text
Process ./papers/my-paper.pdf for my research knowledge base.

Register the source, extract it, ground it faithfully, and create validated research insights.

Preserve null findings, limitations, uncertainty, study design, relationship direction, and causal boundaries.

Do not create social-media content.
```

## Short outcome-first prompt

```text
Process ./papers/my-paper.pdf for my research knowledge base.
```

With the repository `AGENTS.md` active, KnowledgeCraft should identify and use the relevant research skills.

## Ground only

```text
Use research-source-grounder on ./papers/my-paper.pdf.

Create the source card and claim ledger only.
Do not create downstream content.
```

For a registered source, prefer its source ID:

```text
Use research-source-grounder on SRC-123.
```

## Process all new papers

Put multiple papers in:

```text
papers/
```

Then:

```text
Process all new and unfinished research in ./papers through ideas_created.
```

Or use the slash command:

```text
/research-batch

Process all new and unfinished research in ./papers through ideas_created.
```

This should stop at validated research insights unless you explicitly request downstream content creation.

# 6. Research-Library Commands

## OpenCode command

```text
/research-library

Scan ./papers, extract pending sources, and show me the research-library status.
```

## Deterministic CLI

From the project root:

```powershell
python .opencode/skills/research-library/scripts/research_library.py scan ./papers
python .opencode/skills/research-library/scripts/research_library.py extract --pending
python .opencode/skills/research-library/scripts/research_library.py status
```

On Windows with the Python launcher:

```powershell
py .opencode/skills/research-library/scripts/research_library.py scan ./papers
py .opencode/skills/research-library/scripts/research_library.py extract --pending
py .opencode/skills/research-library/scripts/research_library.py status
```

The CLI is useful when you specifically want deterministic library scanning/extraction/status without asking the model to choose the next workflow stage.

# 7. What Happens to the Paper?

The raw paper remains in the input location you supplied.

KnowledgeCraft generates working artifacts under:

```text
.knowledgecraft/research/
```

Typical progression:

```text
papers/my-paper.pdf
       │
       ▼
research-library
       │
       ├→ .knowledgecraft/research/registry/
       └→ .knowledgecraft/research/extracted/
                         │
                         ▼
              research-source-grounder
                         │
                         └→ .knowledgecraft/research/grounded/
                                           │
                                           ▼
                                  research-insight-miner
                                           │
                                           └→ .knowledgecraft/research/insights/
```

A typical grounded source may produce:

```text
.knowledgecraft/research/grounded/SRC-...-source-card.md
.knowledgecraft/research/grounded/SRC-...-claim-ledger.yaml
```

and insight mining may produce:

```text
.knowledgecraft/research/insights/SRC-...-insights.yaml
```

# 8. LinkedIn / Content Mode

Use this when grounded evidence or approved insights already exist.

Typical flow:

```text
grounded evidence / validated insights
        ↓
linkedin-series-architect
        ↓
linkedin-post-drafter
        ↓
author voice / naturalness
        ↓
linkedin-platform-review
        ↓
factuality-guard
        ↓
content-quality-gate
        ↓
qa_approved
```

Scheduling is optional.

## Create a series

```text
Use the validated insights for SRC-123 to create a three-post LinkedIn series.

Preserve source/claim/insight traceability.
Do not invent personal stories or mechanisms.
```

## Draft one post

```text
Draft POST-002 from its validated series brief.

Use only the claims and insights allowed by the brief.
```

## Prepare one post for publication

```text
Take POST-002 through the remaining LinkedIn preparation workflow.

Use my validated author voice profile if available.
Apply naturalness editing only if useful.
Run platform review, factuality review, and final quality review.

Do not schedule or publish.
```

## Schedule approved posts

```text
Create a publishing calendar for the current qa_approved posts.

Cadence: Monday and Thursday.
Timezone: Europe/Helsinki.
Do not invent exact posting times.
```

# 9. Combined Research → LinkedIn Mode

This is the full evidence-to-content workflow.

Start with a paper in:

```text
papers/
```

Then:

```text
Process ./papers/my-paper.pdf into my research knowledge base and then turn the validated insights into a three-post LinkedIn series.

Register and ground the source first.
Create validated research insights.
Create the series and draft each approved brief.
Use my validated author voice profile if available.
Run LinkedIn platform review, factuality review, and final quality review.

Do not publish anything.
```

If you also want scheduling:

```text
After all three posts legitimately reach qa_approved, create a calendar.

Cadence: Monday and Thursday.
Timezone: Europe/Helsinki.
Do not invent exact posting times.
```

For outcome-first orchestration you can explicitly use:

```text
/linkedin-content-pipeline
```

Example:

```text
/linkedin-content-pipeline

Process ./papers/my-paper.pdf from research registration through a three-post LinkedIn series.

Prepare all posts through final QA.
Do not publish.
```

# 10. Automatic Routing vs Direct Skill Use

## Use automatic routing when you know the outcome

Examples:

```text
Process these papers for my research knowledge base.
```

```text
Turn this paper into a LinkedIn series.
```

```text
Get this post ready to publish.
```

```text
Continue from the latest valid stage.
```

KnowledgeCraft should inspect state, reuse valid artifacts, and route to the minimum necessary specialist stages.

## Use a specialist directly when you know the operation

Examples:

```text
Use research-source-grounder on SRC-123.
```

```text
Use research-insight-miner on SRC-123.
```

```text
Run factuality-guard on POST-002.
```

```text
Run linkedin-calendar-planner on the qa_approved posts.
```

# 12. Author Voice Samples

If you want KnowledgeCraft to learn your writing voice, provide **genuine writing samples**.

They can be located anywhere in the project or referenced by path.

A simple optional convention is:

```text
author-samples/
├── article-1.md
├── post-1.md
└── note-1.txt
```

Then ask:

```text
Create an author voice profile from the genuine samples in ./author-samples/.

Do not infer personal facts beyond what is evidenced by the writing samples.
```

Do not use AI-generated examples as if they were genuine author samples.

---

# 13. Resume Instead of Restart

KnowledgeCraft should continue from the latest valid stage.

```text
new
→ research processing
```

```text
extracted
→ grounding
```

```text
grounded
→ insight mining
```

```text
ideas_created
→ series architecture
```

```text
series_planned
→ drafting
```

```text
drafted
→ remaining editing/QA
```

```text
qa_approved
→ calendar, if requested
```

This is why the registry and structured artifacts matter.

---

# 14. Input vs Output Rule

Use this mental model:

```text
INPUT
papers/
author-samples/
explicit file paths
        ↓
KNOWLEDGECRAFT SKILLS
        ↓
OUTPUT / STATE
.knowledgecraft/
```

Do not use `.opencode/skills/` as a working-output directory.

Do not use `.knowledgecraft/research/grounded/` as a place to manually store raw PDFs.

# 15. Validate Your Installation

From the KnowledgeCraft repository:

```powershell
.\scripts\check-all.ps1
```

